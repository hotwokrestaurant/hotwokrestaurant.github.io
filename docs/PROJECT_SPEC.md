# Hot Wok Restaurant — QR Digital Menu: Project Specification

Version 1.0 · Place this file at `docs/PROJECT_SPEC.md`.

---

## 1. Goals

| # | Goal |
|---|---|
| G1 | Customers scan a QR code and see a clear, fast, mobile-friendly menu. |
| G2 | The owner can change prices, mark items sold out, add and delete items **from their phone only**. |
| G3 | Zero running cost, no payment features, no paid tools. |
| G4 | Simple enough for a beginner developer to understand and maintain. |

### Out of scope (v1)
Online ordering, payments, table numbers, customer accounts, reviews, delivery, dish photo upload from the admin page (planned for v2), multiple languages (planned for v2).

---

## 2. Architecture

```
Customer phone ──scan QR──► index.html  (GitHub Pages)
                                │ GET ?action=menu
                                ▼
                    Google Apps Script Web App  ◄──►  Google Sheet
                                ▲
                                │ POST {action, pin, data}
Owner phone ──home icon──► admin.html  (GitHub Pages)
```

- Sheet = database. Apps Script = API. GitHub Pages = static hosting.
- The customer page only reads. The admin page reads and writes.

## 4. API contract (Google Apps Script)

**Base URL:** the Web App `/exec` URL, stored in `js/config.js` as `API_URL`.

All responses are JSON:
```json
{ "ok": true, "data": { ... } }
{ "ok": false, "error": "Human-readable message" }
```

### 4.1 Reads — `GET`

| Request | Returns |
|---|---|
| `GET ?action=menu` | `{ settings, categories, items }` — only visible categories and (unless `show_sold_out`) available items. Used by the customer page. |

### 4.2 Admin — `POST`

**Important (CORS):** send POST bodies with header `Content-Type: text/plain;charset=utf-8` and a JSON string body. This avoids a CORS preflight, which Apps Script does not support. Apps Script responds via a redirect; `fetch` follows it automatically.

Body shape: `{ "action": "...", "pin": "1234", "data": { ... } }`

| action | data | Effect |
|---|---|---|
| `login` | — | Returns `ok: true` if PIN is correct |
| `adminMenu` | — | Returns ALL items and categories (including unavailable) |
| `toggleAvailable` | `{ id, available }` | Updates one item |
| `updateItem` | `{ id, name, category, price, price_large, description, spicy, veg, featured }` | Updates fields |
| `addItem` | same fields, no `id` | Creates item with new id, `available = TRUE`, `sort_order` = last in category |
| `deleteItem` | `{ id }` | Removes the row |
| `moveItem` | `{ id, direction: "up" \| "down" }` | Swaps `sort_order` within the category |
| `updateSettings` | `{ notice, opening_hours, phone }` | Optional, v1.1 |

### 4.3 Server-side requirements
- PIN stored in **Script Properties** as `ADMIN_PIN`. Never hard-coded.
- **Brute-force protection:** use `CacheService` to count failed PIN attempts; after 5 failures, block for 15 minutes.
- **Validation:** trim strings; enforce lengths; prices must be positive integers; category must exist; reject unknown actions and unknown fields.
- **Concurrency:** wrap writes in `LockService.getScriptLock()`.
- **Caching:** cache the `menu` response in `CacheService` for 60 seconds; clear the cache after every successful write so changes appear immediately.
- Set `updated_at` on every write.
- Catch all errors and return `{ ok: false, error }` — never an Apps Script HTML error page.

### 4.4 Deployment notes (put in `apps-script/README.md`)
1. Open the sheet → Extensions → Apps Script → paste `Code.gs`.
2. Project Settings → Script Properties → add `ADMIN_PIN`.
3. Deploy → New deployment → type **Web app** → Execute as **Me** → Who has access **Anyone**.
4. Copy the `/exec` URL into `js/config.js`.
5. **When updating code later:** Deploy → Manage deployments → Edit (pencil) → Version: **New version** → Deploy. This keeps the **same URL**. (Creating a *new deployment* changes the URL and breaks the site.)

## 5. Customer menu — `index.html`

### Layout (top to bottom)
1. **Header:** restaurant name, tagline, optional notice banner.
2. **Sticky category tabs** (horizontal scroll). Tapping scrolls to the section; the active tab highlights while scrolling (IntersectionObserver).
3. **Search box** — filters by item name/description live; shows "No dishes found".
4. **Sections per category** with item cards:
   - Name, description, price (`Rs. 1,200`), and if `price_large`: "Regular Rs. 1,200 · Large Rs. 1,600".
   - Badges: 🌶️ Spicy, 🥬 Veg, ⭐ Chef's special.
   - Photo (if any), lazy-loaded (`loading="lazy"`), fixed aspect ratio to avoid layout jumps.
   - Sold-out items: hidden, or greyed with "Not available today" if `show_sold_out` is TRUE.
5. **Footer:** opening hours, tap-to-call phone button, "Open in Google Maps" link, small "Prices may change" note, small developer credit.
6. **Back-to-top** button after scrolling.

### Behaviour
- Show a **skeleton loader** while fetching.
- Save the last successful menu to `localStorage`; render cached data instantly on next visit, then refresh in the background.
- On failure with no cache → friendly error + call button.
- Must work without photos.

### Visual style
- Warm Chinese-restaurant feel: deep red primary, gold accent, off-white background, dark text. Define as CSS variables.
- Respect `prefers-color-scheme: dark` (optional but nice for dim restaurants).
- System font stack; no web-font download needed.

## 6. Admin page — `admin.html`

Designed for **non-technical owners using only a phone**.

### Screens
1. **PIN screen:** big numeric input (`inputmode="numeric"`), "Login" button. PIN kept in `sessionStorage` (cleared when the browser tab closes). Clear error message on wrong PIN; message when temporarily locked.
2. **Menu manager:**
   - Top bar: "Hot Wok – Menu Manager", **Logout**, link "View customer menu".
   - Category filter dropdown + search.
   - Each item row: name, price, **large availability toggle switch**, ✏️ Edit button.
   - **Toggle** saves immediately and shows a toast "Chicken Kottu hidden from menu" / "…is back on the menu".
   - Floating **"+ Add dish"** button.
3. **Edit / Add form** (full-screen sheet on mobile): name, category (dropdown), price, large price (optional), description, spicy / veg / chef's special checkboxes. Buttons: **Save**, **Cancel**, and on edit **Delete** (red, with "Are you sure you want to delete Chicken Kottu?" confirmation).
4. Optional ↑ ↓ buttons to reorder items.

### UX rules
- Big buttons (≥ 48px), large text, plain English labels (no technical words like "record" or "API").
- Disable buttons and show a spinner while saving; never allow double-submit.
- Every action ends with a clear success or error toast.
- If the session PIN becomes invalid, return to the PIN screen with a message.
- `manifest.json` + icons so the owner can **Add to Home screen** with the name "Hot Wok Menu" and `start_url` = `admin.html`.
- Add `<meta name="robots" content="noindex">` to admin.html.

## 7. QR code — `tools/generate-qr.js`

- Node script using the open-source `qrcode` npm package (dev dependency only).
- Encodes the final customer menu URL (static QR — never expires).
- Outputs `qr/menu-qr.png` (high resolution, ≥ 1000 px) and `qr/menu-qr.svg`.
- Error correction level **M** (or **H** if a logo is placed in the centre later).
- Also generate `qr/table-card.html`: a printable A6 table card with the restaurant name, "Scan for our menu 📱", the QR code, and the short URL underneath.

## 9. Acceptance checklist

- [ ] Customer menu loads in under ~3 seconds on Slow 4G.
- [ ] No horizontal scrolling at 360px width.
- [ ] Wrong PIN rejected; 5 wrong attempts → temporary lock.
- [ ] PIN does not appear anywhere in the GitHub repository.
- [ ] Price change in admin → visible on customer menu after refresh.
- [ ] Sold-out toggle hides the item for customers.
- [ ] Menu still shows (from cache) when the network fails.
- [ ] Item names containing `<script>` display as plain text (XSS test).
- [ ] QR tested on at least 3 different phones.
- [ ] Owner Guide written in simple language.
